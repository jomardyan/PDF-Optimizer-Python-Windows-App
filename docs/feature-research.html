PRODUCT RESEARCH & IMPLEMENTATION BRIEF · 7 SEPTEMBER 2026

Make repeat PDF batches easier

For the owner of PDF Optimizer. Scope: the existing Windows desktop app, local processing, preservation of original files, and practical additions to the current interface.

Decision: prioritize saved settings, targeted retries, and exportable results. Your stated preference confirms this direction. Reusable queues, queue ordering, and direct document opening complete the same workflow.

Why this direction fits

PDF24 documents remembering compression settings, while PDFsam documents saved workspaces that restore tool configuration. These provide established examples for reducing repeated setup. They do not measure demand among this app’s users. PDF24 Creator changelog · PDFsam workspaces

Adobe’s guided actions expose processing reports and let users stop and resume work while retaining processed outputs. For this app, retrying only failed or canceled items and exporting a CSV are implementation choices based on that broader pattern and your preference. Adobe guided actions

What was added

FunctionBehavior and where to find it
Saved preferencesCompression strength, appearance, and output folder are remembered locally. Reset them through the ••• menu.
Targeted retryRetry unfinished processes failed and canceled items using the current settings. Completed outputs remain available; signed or encrypted skips are excluded.
Export resultsExport CSV saves the latest attempt for each processed item still in the queue, including failures and cancellations. It includes paths, sizes, savings, status, timing, and messages.
Reusable queues••• → Queue, or Ctrl+S / Ctrl+L, saves and loads ordered sources and settings. Loading never starts processing.
Queue controlsAlt+Up / Alt+Down changes order. Optimize selected runs a single queued item.
Inspect documentsOpen original and Open optimized copy use the existing default viewer. Folder items open in Explorer.

Alternatives considered

Page tools are a reasonable later expansion: PDFsam offers merge, split, rotation, and extraction. However, pikepdf’s page-copying examples warn that document-level metadata and bookmarks do not transfer automatically. That adds preservation work beyond this batch improvement. PDFsam documentation · pikepdf page assembly

An embedded page preview would require another renderer because pikepdf does not rasterize pages. Opening documents in the installed viewer avoids that dependency for this release. This is an engineering tradeoff, not a claim that integrated previews lack value. pikepdf capabilities

Limits and verification

  • Queue files store paths and settings, not PDFs or past results. Missing sources are reported. Invalid imports leave the current queue intact.
  • Reports cover the current queue’s latest attempts. Removing or clearing items removes their records; export first to retain them. Folder byte totals count PDFs only.
  • Preferences and exports use atomic writes. Tests check retry isolation, reporting of unsuccessful attempts, queue restoration, invalid input handling, and preference persistence.
  • Product documentation and the stated user preference support prioritization. No user study, comparative speed benchmark, or market-demand estimate was performed.
